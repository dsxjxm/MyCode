# 教师后台可配置单个文件上传大小

## Context

当前 WWW 固定为 20 MiB，FTP/Telnet、邮件附件、学生名单导入固定为 10 MiB，教师无法调整；邮件前端也写死 10 MiB，修改后端后仍会被前端拦截。需要在教师后台增加统一开关与各模块自定义值，保存后立即生效，并保持旧数据升级后的默认行为不变。

## 实施方案

### 1. 集中保存并校验上传大小配置

修改 `server/services/uploadRules.js`，在现有扩展名规则旁增加大小配置，继续复用 `app_settings` 表，不新增数据库表：

- 配置结构：`{ enabled: boolean, valuesMiB: { www, terminal, mail, students } }`。
- 默认值：开启；WWW 20、FTP/Telnet 10、邮件附件 10、学生名单导入 10 MiB，与当前行为一致。
- 各值接受 1～1024 的整数；非法输入返回 400。关闭开关时保留数值，重新开启可恢复。
- 提供运行时读取方法：开启时返回对应字节数，关闭时返回 `Infinity`；每次请求读取，不缓存、不需重启。
- 旧数据库无配置或配置损坏时回退到默认值，避免意外变成不限。

### 2. 四个上传入口改为动态限制

当前锁文件中的 Multer 2.5.0 已支持 `limits(req)`，直接复用该能力：

- `server/routes/space.js`：WWW 使用 `www` 配置。
- `server/routes/terminal.js`：终端 multipart 上传使用 `terminal` 配置。
- `server/routes/mail.js`：邮件附件使用 `mail` 配置。
- `server/routes/students.js`：名单导入使用 `students` 配置。
- 保留 `server/index.js` 现有 `LIMIT_FILE_SIZE -> HTTP 413 JSON` 处理。

### 3. 封闭 FTP/Telnet 实际上传旁路

修改 `server/routes/terminal.js` 与 `public/assets/js/terminal.js`：

- `/api/terminal/exec` 同时支持可选 multipart 文件；学生端选择文件后直接以 FormData 提交文件、命令和终端状态，不再先把大文件读成 JSON。
- 保留现有 `/api/terminal/upload` 和 JSON 调用兼容性。
- JSON 中的 `upload.content` 仍按 UTF-8 实际字节数校验大小，并沿用现有扩展名校验。
- FTP 与 Telnet 共用 `terminal` 设置，避免同一文件写入入口出现不同规则。

这样教师把终端阈值调到 10 MiB 以上时，不会再被全局 8 MiB JSON 请求体限制卡住；关闭开关表示不再施加业务单文件上限。

### 4. 邮件前端读取动态限制

修改 `server/services/mailSim.js`、`server/routes/mail.js`、`public/assets/js/mail.js` 和必要的邮件提示：

- `attachmentLimits()` 返回当前邮件附件限制；关闭时用 `null` 表示单附件不另设上限。
- 通过现有 `/api/mail/config` 向邮件页下发该值。
- 删除前端固定 10 MiB 判断和固定提示，改为按当前配置提示、预检；服务端仍为最终校验。
- 保留“最多 5 个附件”和邮件服务器现有“最大邮件大小”设置，两者不与本次单附件开关混用。

### 5. 扩展教师 API 和后台界面

修改 `server/routes/admin.js`、`public/admin.html`、`public/assets/js/admin.js`：

- `GET /api/admin/upload-settings` 同时返回扩展名白名单和大小配置。
- `PUT` 按字段是否出现分别更新，确保只保存扩展名时不清空大小配置，只保存大小时也不清空扩展名；先校验再写入。
- 在模块管理现有上传类型面板旁新增“单个文件上传大小限制”：一个总开关、WWW、FTP/Telnet、邮件附件、学生名单导入四个数值输入框及独立保存按钮。
- 关闭时禁用数值框但保留值；显示单位和内存占用提醒（当前上传使用内存暂存，关闭或设置过大可能增加服务内存压力）。

## 验证

1. 在 `test/core.test.js` 增加配置默认值、持久化、非法值、开关关闭/重开、字节换算及扩展名互不影响的测试，运行 `npm test`。
2. 启动独立临时数据目录服务，教师后台修改 WWW 阈值：超过阈值返回 413；无需重启调大后同一文件可上传。
3. 分别验证 WWW、邮件附件、名单导入、FTP/Telnet 的允许与超限场景；关闭总开关后不再施加业务单文件上限，重新开启恢复原值。
4. 验证邮件页面不再固定拦截 10 MiB，最多 5 个附件和最大邮件大小规则保持不变。
5. 检查学生无权修改教师设置，保存后重启服务配置仍保留，并确认前端能显示 413 错误信息。

本次只实现和验证功能；版本号、云端发布与离线安装包重打需另行确认。
